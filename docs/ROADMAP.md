## 一、基本功能：没有就不算可用

这一层管“看清楚”：打开仓库，马上能看懂发生了什么。

| 功能 | 要求 | 状态 | 现状和缺口 |
|---|---|---|---|

| | 每行显示短 hash、提交信息、作者、相对时间 | 🟡 | 都有，但时间是完整日期，不是相对时间 |

## 二、重要功能：拉开差距、让人愿意天天用

这一层管“能理解”和“能顺手操作”。可视化工具最大的价值在于让人**操作前就看懂后果**。

| 功能 | 要求 | 状态 | 现状和缺口 |
|---|---|---|---|
| 常用写操作 | 暂存、取消暂存 | 🟡 | 只能按文件，不能按 hunk 或单行 |
| | 提交、切换、新建、删除分支 | ✅ | 还有修改上次提交、重命名分支、打标签、克隆 |
| | fetch、pull、push | 🟡 | 没有单独的 fetch；pull 固定 `--no-rebase` |
| 操作预览和撤销 | merge、rebase、cherry-pick、reset 前在图上预览结果 | ❌ | 只有确认对话框 |
| | 拖拽分支完成 rebase 或 merge | ❌ | 没有 rebase |
| | 每次操作都能撤销（靠 reflog） | ❌ | |
| 冲突解决 | 三方对比，逐块选择保留哪一边 | 🟡 | 能按块选我方、对方、两者，能中止和继续；不显示 base，不能手动编辑 |
| Blame 和文件历史 | 看每行是谁在哪次提交改的，并能一路追溯 | 🟡 | 能跳到提交；不能直接往前一个版本继续追溯 |
| 两个引用对比 | `main...feature` 各自领先的提交和文件差异 | ❌ | |
| Reflog 视图 | 找回丢失的提交 | ❌ | |
| 多仓库 | 最近仓库、快速切换 | ✅ | |
| 键盘操作 | j/k 移动、快捷键执行命令 | ❌ | |

## 优先级

1. **补第一层的缺口**：分支颜色稳定、去掉 5000 条上限改为继续加载、语法高亮、权限变化显示、提交者、只看某条分支。大仓库性能和图的可读性是可视化工具的根本。
2. **第二层先做 reflog 视图和撤销**，再做图上预览。这是可视化相对命令行的独有优势。写操作都集中在 `GitCli`，每次操作前记下 HEAD 就能撤销。
3. 然后做 hunk 级暂存和键盘操作。
4. 第三层等核心稳定后，按目标用户挑一两个做。
