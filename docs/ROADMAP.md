## 一、基本功能：没有就不算可用

这一层管“看清楚”：打开仓库，马上能看懂发生了什么。

| 功能 | 要求 | 状态 | 现状和缺口 |
|---|---|---|---|
| 提交图 | 分支、合并的走线清楚 | ✅ | `GraphLayout.kt` 分配列，`GraphCell.kt` 画线 |
| | 颜色稳定：同一条分支始终同一个颜色 | ✅ | 颜色按分支名分配（`BranchColors`），图、标签、侧边栏圆点同色；悬停或选中提交时只亮那条线 |
| | 每行显示短 hash、提交信息、作者、相对时间 | ✅ | 相对时间每分钟刷新，悬停看完整时间；时间取作者时间 |
| | 几万个提交也流畅（虚拟滚动、按需加载） | ✅ | `CommitPager` 每页 2000 条，滚到底自动继续加载；每页读取和重排都在后台线程。图最多占列表宽度的 40%，放不下的列在边上画三个点 |
| 引用展示 | 本地分支、远程分支、标签、HEAD、stash | ✅ | 储藏在侧边栏有单独分区；图上画成空心方块，挂在储藏时所在的提交上方，右键去储藏页 |
| | 点侧边栏的 ref 跳到对应提交 | ✅ | 提交还没加载时自动往下读到它，状态栏可以取消；详情里的父提交、Blame 同样能跳 |
| 提交详情 | 完整信息、父提交、作者和提交者 | ✅ | 默认选中第一条；详情、文件和 Diff 放在底部浮层，首次上滑、切换提交直接刷新，可拖动顶边调高或点击中央箭头展开覆盖整个主区域/恢复默认高度，列表底部留白避免遮挡末尾提交；提交者和作者不同时单独一行；合并提交可选和哪个父提交比较 |
| | 改动文件和每个文件的增删行数 | ✅ | |
| Diff | 统一视图和左右对比 | ✅ | 带行号 |
| | 二进制、重命名、权限变化正确显示 | ✅ | 文件列表标出权限变化，diff 顶部说明；提交详情、本地改动、储藏三处一致 |
| 工作区状态 | 已暂存、未暂存、未跟踪、当前分支 | ✅ | 监听文件变化后刷新（两次至少隔 1.5 秒），另每 30 秒兜底一次；监听不了时每 3 秒轮询 |
| 搜索和过滤 | 按提交信息、作者、hash 搜索 | ✅ | 已加载的即时过滤，同时在后台搜全部历史；列表底部提示没加载的部分还有多少匹配，点击加载 |
| | 只看某一条分支 | ✅ | 悬停侧边栏的分支或图上的线、选中提交时，只亮这条线（沿第一个父提交往下），其他线变暗。其他分支的提交仍在列表里，真正的过滤见第二层“分支过滤” |
| | 只看某个文件的历史 | ✅ | 文件历史标签里点“在主图中只看这个文件”，父提交改写成过滤后的祖先，图连得上；JGit 改写父提交要先读完整个历史 |

## 二、重要功能：拉开差距、让人愿意天天用

这一层管“能理解”和“能顺手操作”。可视化工具最大的价值在于让人**操作前就看懂后果**。

| 功能 | 要求 | 状态 | 现状和缺口 |
|---|---|---|---|
| 常用写操作 | 暂存、取消暂存 | ✅ | 文件／hunk／单行，统一与并排 Diff 共用选择；完整补丁经临时 index 校验后锁内原子安装；二进制等明确回退整文件 |
| | 提交、切换、新建、删除分支 | ✅ | 还有修改上次提交、重命名分支、打标签、克隆 |
| | merge、rebase、cherry-pick、revert、reset | ✅ | 普通 rebase 保留合并拓扑，支持重启继续／跳过／保留空提交／中止及整次撤销；reset 支持三种模式，四种操作统一预览 |
| | 储藏：保存、查看、apply、pop、drop | ✅ | 储藏页可看每个文件的 diff |
| | fetch、pull、push | ✅ | 独立 fetch；pull 支持 merge／rebase／ff-only，先显式获取所选远程分支再预览集成；按仓库保存策略，支持无上游选择与自定义 refspec |
| 操作反馈 | 进行中、成功、需处理和失败有明确提示 | ✅ | 共用顶部反馈条；成功 5 秒后收起，悬停或展开详情时保留，警告和失败手动关闭；完整输出可展开、选中和复制，提供重试、先拉取或放弃；本地改动、分支、储藏、冲突保存、克隆和文件忽略操作接入统一异常处理，执行期间阻止重复写入 |
| 操作预览和撤销 | merge、rebase、cherry-pick、reset 前在图上预览结果 | ✅ | 独立仓库演练与独立图布局，展示 HEAD／index／工作区差异、分支移动、冲突与独立的后续预计拓扑；执行前校验预览是否过期 |
| | 拖拽分支完成 rebase 或 merge | ✅ | 侧边栏／图标签拖拽到分支，选择方向后统一预览；分支切换同一恢复事务，中止安全返回原分支并保留额外本地改动 |
| | 每次操作都能撤销（reflog 与本地恢复点） | ✅ | 独立对象与文件恢复存储，恢复 HEAD、引用、index、工作区和 stash 顺序；默认 30 天／2 GiB，外部修改需显式恢复；不反向推送或删除克隆目录 |
| 冲突解决 | 三方对比，逐块选择保留哪一边 | ✅ | index stage 1/2/3 来源、可展开 base、块选择与全文编辑；文件切换保留草稿，保存核对外部修改，二进制／删除支持整文件选择 |
| Blame 和文件历史 | 看每行是谁在哪次提交改的，并能一路追溯 | ✅ | 保留来源路径与行号，支持重命名追溯、父版本区间、合并父选择、删除前版本和前后导航；新增行到引入处终止 |
| 两个引用对比 | `main...feature` 各自领先的提交和文件差异 | ✅ | 双向独有提交计数与独立分页，固定 OID；共同祖先→B／A→B 文件差异，多共同祖先选择、无祖先提示、交换和刷新 |
| 分支过滤 | 只列出一条或几条分支历史上的提交，和 `git log <branch>` 一样 | ✅ | 本地／远程分支多选并集，与文件过滤组合；分页和搜索共用引用快照，失效引用明确提示 |
| Diff 语法高亮 | 按文件类型给代码着色 | ✅ | Kotlin／Java／JS／TS／JSON／Python；提交、本地、stash、引用对比共用，旧新源码独立后台分词；1 MiB／20,000 行回退，32 MiB 缓存 |
| Reflog 视图 | 找回丢失的提交 | ✅ | HEAD 或指定引用分页查看，按 OID 打开不可达提交，从操作前／后创建恢复分支；对象被清理时提示 |
| 多仓库 | 最近仓库、快速切换 | ✅ | |
| 文件浏览 | 按目录看工作区的所有文件，包括被忽略的 | ✅ | 侧边栏“文件”：左边目录树，右边当前目录的文件表（状态、大小、修改时间）。目录从磁盘读，git status 只标状态、补上还没提交的删除；被忽略的标灰，可以隐藏。不预览内容，双击交给系统打开；右键在 Finder 中显示、复制路径、查看改动、查看历史、把未跟踪的文件加入 .gitignore。已经提交的删除不显示，看历史 |
| 键盘操作 | j/k 移动、快捷键执行命令 | ✅ | 图与分支列表焦点导航；共享命令菜单／面板与 Cmd/Ctrl 快捷键，输入框保留文本撤销，Esc 退出搜索／选择不终止 Git |

## 优先级

第一层已全部完成（2026-11-05），第二层功能已实现（2026-11-06）。

1. 继续维护恢复、并发写入和崩溃恢复回归；Git 2.50+ 的原生引用事务在持锁时核对旧值。
2. 操作预览保持隔离演练与预计拓扑分开；后续冲突、外部驱动与 hooks 不标记为已验证。
3. 保持大历史分页、后台 Diff 分词和恢复存储配额约束。
4. 第三层等核心稳定后，按目标用户挑一两个做；不扩展本轮范围。
